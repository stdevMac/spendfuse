A spending firewall for AI agents

Spendfuse is a vault contract on NEAR. Your agent gets a key that can only ask the vault to pay. Limits, approvals and canaries decide on chain, before any money moves.

Three checks between your agent and its money

The agent never holds funds. It holds a function-call key that NEAR itself limits to three methods on one contract.

  1. 1

    Fund the vault, not the agent.

    The owner deposits NEAR into vault.tw-firewall-demo.testnet and registers the agent with a policy: caps, a rolling 24h limit, an approval threshold, an allowlist.

  2. 2

    Give the agent a narrow key.

    Its key can call request_payment, report_receiver and self_freeze on the vault, with a 1 NEAR gas allowance. The protocol rejects transfers, new keys, other contracts and attached deposits.

  3. 3

    Let the firewall contract decide.

    Each request runs the policy in a fixed order. The first match decides: paid, held for your approval, blocked, or tripped and frozen. The model only hears "paid", "refused" or "pending human approval".

The agent key cannot leave the vault.

In the stolen-key run, five escape attempts died at the protocol's access-key layer. No transaction landed, so there is nothing to link. That is the result.

What the firewall enforces, and what only advises

The contract is the only part that can say no to money. The off-chain guard probes canaries, checks payees and warns, and anyone holding the agent key can skip it.

  • Enforced on chain

    Caps, rolling 24h limit, hourly rate, allowlist, blocklist, approval queue, canaries, auto-freeze.

  • Advisory, off chain

    Guard and scout checks. They depend on FastNEAR and NearBlocks.

  • Owner

    Full trust: approves, unfreezes, withdraws, changes policy. One full-access key plus 1 yoctoNEAR per call.

  • Guardians

    Can only tighten: freeze, pause, reject, block, add canaries.

Your agent calls one method

The TypeScript client in src/lib/spendfuse.ts wraps every contract call and decodes the result. Native NEAR only.

What request_payment gives back
result.statusWhat your agent should do
paidCarry on. The transfer settled.
pending_approvalWait. Only the owner can approve it; the owner or a guardian can reject it, and it expires after 24h.
blockedStop and read result.reasons. Do not retry the same payment.
trippedStop. A canary was hit and the agent is frozen until the owner unfreezes it.

agent.ts

import { agentApi, NEAR } from './src/lib/spendfuse.ts';
import { makeProvider, signerFromSecret } from './src/lib/near.ts';

const agent = agentApi(
  { accountId: 'agent.tw-firewall-demo.testnet',
    provider: makeProvider(),
    signer: signerFromSecret(loadAgentKey()) },  // your code: the function-call key only
  { vaultId: 'vault.tw-firewall-demo.testnet' },
);

const { result } = await agent.requestPayment({
  receiver_id: 'store.tw-firewall-demo.testnet',
  amount: 3n * NEAR / 10n,                          // 0.3 NEAR
  memo: 'order 1042',
});

// result.status: 'paid' | 'pending_approval' | 'blocked' | 'tripped' | 'expired' | 'transfer_failed'
if (result?.frozen) await notifyOwner(result.reasons);  // your code

import { makeProvider, signerFromSecret } from './src/lib/near.ts';

const owner = ownerApi(
  { accountId: 'tw-firewall-demo.testnet', provider: makeProvider(),

What Spendfuse does not stop yet

Read this before you put real money behind an agent. Mainnet is not deployed and the contract is not audited.

Salami under the new-payee limit
Bounded, not stopped. Without allowlist_only, a stolen key can pay fresh payees up to 0.2 NEAR each without approval: about 2.85 to 3 NEAR per rolling 24h with the demo policy, every 24h, until you freeze it.
The owner key
Total trust. Whoever holds it can approve, unfreeze, withdraw and change the policy.
The vault's own full-access key
Still present on testnet: lockdown has not been run. Its holder can redeploy the contract or move the balance.
Canary hashes
Unsalted, so anyone with a candidate id can check it in public state. Ids are random 64-hex accounts, and a tripped canary's id becomes public. Canaries only catch an attacker who tries to pay them.
The off-chain guard
Advisory. Anyone with the agent key can skip it, its canary probe depends on the contract's storage layout, and the scout depends on FastNEAR and NearBlocks.
Guardians
Can pause, freeze and reject everything, and can lock vault storage with up to 1000 blocklist entries and 1000 canary hashes.
Reports
Can be used to slow payments to a payee by sending them to the approval queue. They cannot move funds.
Environmental blocks
A block caused by the vault's own state, such as a low balance, never counts toward auto-freeze.
The proof run
A scripted model played the agent. No live LLM was in the loop.
Scope
Native NEAR only, no fungible tokens. Testnet only. Not audited.
